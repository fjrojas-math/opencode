# Journal — 2025-09-13

## RAG: Analysis and Patterns for Code Assistants

### 1. Standard RAG Pattern in Code Assistants

- **Indexing:** Chunk code/documentation and convert to embeddings; store in a vector store (local or external).
- **Retrieval:** Embed the user's question; perform semantic search in the vector store; retrieve top-K relevant fragments.
- **Generation:** The LLM receives the user's prompt plus the automatically retrieved fragments.
- **Automation:** The user does not need special commands; context is injected into every query.
- **Multiple sources:** It is viable and recommended to combine repo context and external sources (official docs, forums, articles, etc.).

### 2. Differences with opencode's current flow

- **Current:** Textual and heuristic search (grep, ls, read); fragment selection by literal match.
- **True RAG:** Semantic search (embeddings); finds relevant fragments even if there is no literal match.
- **Both:** Inject relevant context into the prompt, but RAG does so more precisely and at scale.

### 3. Advantages of Automatic RAG

- More precise and contextualized answers.
- Scales to large projects and poorly documented code.
- Enables enriching context with external information.

### 4. Suggested next steps

- Document configuration examples and automatic flows.
- Prototype mixing internal and external context in the RAG pipeline.
- Keep this journal as a living log of analysis and experimentation.
